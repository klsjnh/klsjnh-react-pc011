## 1. 文件头（rule: `file-header`）【正则】

每个 `.ts` / `.tsx` 文件在 import 之后、代码之前是 klsjnh 文件头块：**头块与 import 之间空一行**，头块 `*/` 与首个声明之间**空一行**；history 行用**小写描述**（禁止写文件名 / 组件名）。

```ts
import type { JulyUserVo011 } from '@/types/system011/julyUser'

/*                july user api
 *
 *      @author     xiangrkrs@163.com
 *      @version    ver 0.0.1
 *      @createdate 2026.09.14
 *      @modifydate
 *
 *===========================================
 *          modify history
 *
 *      2026.09.14  july user api client
 *
 */

export const julyUserApi = {
```

**豁免**：纯 barrel 文件（只有 `export ... from`）、类型声明文件（`*.d.ts`）、配置文件（`vite.config.ts` / `eslint.config.js`）。

违规示例（门禁会拦）：history 行写 `julyUser.ts`（文件名而非描述）；头块紧贴 import；头块后直接接代码。

## 2. 注释规范

### 2.1 公共 API 必须有 JSDoc（rule: `jsdoc-public`）【正则】

**导出**的函数 / 组件 / hook / 类型 / 常量必须有 JSDoc，说明**用途与关键约束**（不是复述签名）：

```ts
/**
 * 分页查询用户列表。
 *
 * @param params 分页与过滤条件（字段名以后端 OpenAPI 为准）
 * @returns 分页结果，`list` 为当前页数据
 */
export const selectJulyUserListByPage = (params: JulyUserQuery011) => { ... }
```

### 2.2 JSDoc 语言（rule: `jsdoc-language`）【正则】

- **类型定义、工具函数、公共组件**的 JSDoc 用**英文**（与后端 `*Vo011` 规范对齐，便于跨语言复用）。
- **业务钩子与页面组件**的 JSDoc 允许**中文**（业务语境优先可读性）。
- 同一文件内**不混用**（择一），文件内保持一致。
- `@param` / `@returns` / `@throws` 等标签名一律英文。

### 2.3 禁止注释掉的代码（rule: `no-commented-code`）【正则】

- **禁止**保留无说明的注释代码块（`// const old = ...`）。
- 需要保留历史 → **git 负责**；需要说明「为什么不用某方案」→ 写成**文字说明**，不是留着代码。

```ts
// ❌ 禁止
// const result = await fetch(url)
// return result.data

// ✅ 允许：解释性文字
// 兼容后端 statusCode 非 200 但带 data 的历史行为，暂不收敛（见 docs/{date}.md）
```

## 3. 类型规范（rule: `type-*`）【TS】

### 3.1 禁 `any`（rule: `no-any`）【TS + ESLint】

- **禁止** `any`、`as any`、`<any>`。
- **禁止** `@ts-ignore`；确需抑制用 `@ts-expect-error` **并附原因注释**，且必须经评审。
- 未知类型用 `unknown` + 收窄，不用 `any` 糊。

```ts
// ❌
const data = res as any

// ✅
const data = res as JulyUserVo011
// 或
const raw: unknown = await res.json()
if (!isJulyUserVo011(raw)) throw new Error('unexpected payload')
```

### 3.2 禁非空断言滥用（rule: `no-nonnull-assert`）【ESLint】

- **禁止**在业务代码中用 `!` 强行断言（`el!`、`data!`）。
- 允许场景：`document.getElementById('root')!`（入口挂载，React 官方模板同款）等**明确不可能为空**的初始化代码。
- 其余一律用**判空 + 早返回**。

### 3.3 类型分层（rule: `type-layout`）【正则】

- 类型**按域分文件**，见 [017.tech-debt-redlines](017.tech-debt-redlines.md) §B1。
- **禁止**把域实体堆在 `types/index.ts`；该文件只做 barrel 转出。

### 3.4 一字段一名（rule: `field-alias`）【正则】

**禁止**以下别名（真实债，见 [017.tech-debt-redlines](017.tech-debt-redlines.md) §B2）：

| 禁用 | 统一为 |
|------|--------|
| `passWord` | `password` |
| `createDate` / `updateDate` | `createTime` / `updateTime` |
| `remark011` / `remark013` | `remark` |
| `version011` / `version013` | `version` |

> 字段名唯一真源 = **运行时 OpenAPI 快照**；前端类型与之**逐字一致**。

### 3.5 可选性精确（rule: `optional-strict`）【评审】

- 后端必出字段**不得**加 `?`；可能为 `null` 用 `| null`。
- 分页 / 信封等公共类型的可选性以 `013.api-contract.md`为准。

### 3.6 代际后缀（rule: `naming`）【正则】

按「目录 → 必须后缀」检查**导出类型与组件**名：

| 类别 | 后缀 | 例子 |
|------|------|------|
| 传输载荷（入参 / 出参） | `*Vo011` | `JulyUserIdVo011` / `JulyUserSaveVo011` |
| 分页对（自带方向语义，**例外**） | `*Query011` / `*Result011` | `PageQuery011` / `PageResult011` |
| 统一响应信封 | `Response011` | `Response011<T>` |
| 实体 View Object | `*Vo011` | `JulyUserVo011` |
| 枚举 / 配置常量 | 语义名 + `011` | `Status011` / `HttpStatus011` |
| 自定义组件 | 语义名 + `011` | `KlsjnhSql011` |

## 4. 命名规范（rule: `naming-file` / `naming-symbol` / `july-prefix`）【正则】

| 对象 | 规则 | 示例 |
|------|------|------|
| 页面组件文件 | `PascalCase.tsx`（与路由/菜单 key 同名） | `JulyUserList.tsx` |
| 通用组件文件 | `PascalCase.tsx` | `MessageBridge.tsx`（`components/` 下，**不加** `july`） |
| 组件目录 | `camelCase/` | `julyUser/` |
| 工具 / 服务 / store 模块 | `camelCase.ts` | `request.ts` / `julyUser.ts` |
| 类型文件 | `camelCase.ts` | `julyUser/vo.ts` / `api.ts` |
| 导出组件名 | `PascalCase` | `JulyUserList` / `KlsjnhSql011` |
| 导出函数 / hook | `camelCase`，hook 以 `use` 开头 | `selectUserListByPage` / `useTableFillHeight`（`useTable` `[PLANNED]`） |
| 常量 | `SCREAMING_SNAKE_CASE` | `MAX_PAGE_SIZE` |
| 枚举成员 | `PascalCase` | `Status011.Enabled` |

**禁止缩写（rule: `no-abbreviation`）【正则】** —— 目录 / 文件 / 变量名**一律用完整词**，不缩写（`common` 不写 `comm`、`configuration` 不写 `conf`、`component` 不写 `comp`、`message` 不写 `msg`）。**例外**：`api` / `utils` / `props` / `ref` / `src` / `env` / `config` 等**业界已固化**的写法。

> **动因**：缩写靠约定记忆维持（`comm` 到底指 `common` 还是 `command`？），新人 / AI 都要额外推断；完整词自解释、可被 grep 精确命中。**目录名是长期资产，值得多打几个字符。**

**`july` 前缀（业务对象命名，rule: `july-prefix`）【正则】** —— 对齐后端实体 `JulyUser` / 表 `july_user` / VO 目录 `julyuser/` / URL 段 `julyUser`，**四种形态一体**：

| 形态 | 写法 | 示例 |
|------|------|------|
| 文件 / 目录 | `july` + PascalCase 首字母小写 | `julyUser.ts` · `julyUser/` · `julyDept.ts` |
| 类型 | `July` + PascalCase + 代际后缀 | `JulyUserVo011` · `JulyRoleQuery011` |
| 函数 / 变量 | 动词 + `July` + PascalCase | `selectJulyUserListByPage` · `buildJulyDeptTree` |
| 组件文件 | PascalCase（含 `July`） | `EditJulyUser.tsx` · `JulyRoleList.tsx` |

**例外（不加前缀）**：① 通用领域概念字段（`auth` store 的 `user` / `token`）；② 框架级 / 跨域通用组件（`components/layout/`，以及 `[PLANNED]` 的 `components/common/`）；③ 非 IAM 的其他域（沿用各自后端实体前缀，如 `storageCenter` 域）。

- **路由收敛到单一真源** `src/config/routes.ts`（路径常量 + 懒加载映射）；**禁止**组件内 `switch` / 字符串分派与 `ALIAS` 别名表（见 [017.tech-debt-redlines](017.tech-debt-redlines.md) §A2）。`[PLANNED]` 「路由 key = 页面文件名 = 菜单 key，三者同名」尚未达成。

## 4.1 API 函数名（rule: `api-endpoint-verb`）【正则】

**函数名逐字对齐后端端点动词，禁止改成前端习惯语序**：

| 后端端点 | 前端函数 | 说明 |
|----------|----------|------|
| `/selectListByPage` | `selectUserListByPage` | 分页（**不是** `getUserList`） |
| `/getById` | `getRoleById` | 详情 |
| `/insert` | `insertOrganization` | 新增 |
| `/update` | `updateOrganization` | 修改 |
| `/delete` | `deleteOrganization` | 删除（**按端点实际名**，勿臆造 `logicDelete`） |

> **现状**：多数函数已对齐端点动词；仍有少量沿用 `fetch*`（`fetchUserPage`）/ `load*`（`loadRoles`）/ `add*`（`addRole`）写法，尚未全量收敛。

> **动因**：端点名是运行时 OpenAPI 的 `operationId`，函数名逐字对齐后「搜端点名 → 找到同名函数」零歧义；一旦翻译成语序不同的名字，映射就靠记忆维持 = 技术债。分页 `*Query011` / `*Result011` 命名规则**不受影响**（保留）。
>
> **本工程实际写法**：函数名 = **动词 + 业务对象**，**不叠 `July` 中缀**（`July` 只出现在**类型名**里）。删除动作按端点实际名（`deleteOrganization`），**不强行改写成 `logicDelete`**。

## 5. 导入规范（rule: `import-order`）【正则】

- **禁止**跨层乱序（如把 `antd` 混在 `@/` 内部之间）。
- **禁止**深层相对路径穿透（`../../../api/request`）——跨目录一律用 `@/`。

## 6. 路径别名（rule: `path-alias`）【正则】

- **禁止**跨目录相对路径 `../`；**同目录内部件**（`./columns`）允许。
- 一律使用 `@/` 别名（`@` → `src`）。
- 判定：出现 `../../` 即违规。

## 7. 请求与状态（rule: `request-layer` / `state-layer`）【正则 + 评审】

- **信封解析收口在 `src/api/request.ts` 一处**，业务层**禁止**再判 `statusCode === 200`（§C5）。
- **401 处理收口在同一处**：清本地会话 → 由路由守卫（`App.tsx` 订阅 `authStore`）跳登录；凭据类接口（`login` / `logout`）除外；**不做静默刷新 / 重试**。
- **业务请求函数放 `src/services/{域}/`**（`src/api/` 只保留 `request.ts` 的 mock / 真实后端分流），必须声明泛型返回类型：

```ts
// src/services/system011/julyUserService.ts
import { api } from '@/api/request'
import { SYSTEM011_ACTIONS } from '@/services/system011/actions'
import type { JulyUserVo011, PageResult011 } from '@/types/system011'

/** 用户分页查询 */
export function selectUserListByPage(body: object = {}): Promise<PageResult011<JulyUserVo011>> {
  return api.post<PageResult011<JulyUserVo011>>(SYSTEM011_ACTIONS.user.selectListByPage, body)
}
```

- **全局状态只用 Zustand**（`src/stores/`）；**禁止**手写 pub/sub、`listeners: Set`、`emit()`（§A1）。
- **状态写入口径**：本项目采用「service 编排 + 写 store」——service 调 api 后可写 `stores/`；唯一反向例外是 `stores/authStore.ts` 调用服务层登录 / 登出。
- `[PLANNED]` **CRUD 工厂**（`useCrudTable` / `createCrudStore`）尚未实现，当前各域 service 各自编排（§A4 口径随之待裁决）。

## 8. 组件规范（rule: `component-*`）【正则 + 评审】

### 8.1 组件形态

- **一页一组件** → 单文件 `JulyUserList.tsx`。
- **一页多组件**（列表 + 独立编辑页等）→ 必须建目录：

```text
src/pages/system011/julyUser/
├── index.tsx           # Barrel or page entry
├── JulyUserList.tsx
└── EditJulyUser.tsx
```

### 8.2 组件职责边界（【评审】，对齐 §A2 口径）

**`components/` 三分类**：

| 子目录 | 放什么 | 判定 |
|--------|--------|------|
| `layout/` | 全局布局壳（`index.tsx` / `Left.tsx` / `Top.tsx`） | 每个页面都被它包住 |
| `common/` | `[PLANNED]` 尚未建立；约定放与业务无关的通用件（如 `OrgTree.tsx`） | 换一个业务域也能原样复用 |
| `{domain}/` | 域内跨页复用块（如 `system011/`） | 只在某一个域内跨页复用 |

| | `pages/` | `components/` |
|--|----------|---------------|
| 角色 | 路由入口、一页一事 | 被**多个**页面引用的块 |
| 进菜单 / 路由 | 是 | 否 |
| 单页专用子弹窗 / 表单 | 留在页面内 | **不要**塞进 `components/` |

**判定口诀**：去掉路由后仍值得独立复用 → `components/`；只服务一个路由页 → 留在 `pages/`。

**升级路径（只允许向上）**：`pages/` 单页私有 → `{domain}/` 域内跨页 → `common/`（`[PLANNED]`）业务无关通用。**禁止**反向塞。

**`common/` 硬约束**（`[PLANNED]`，目录建成后生效）：**禁止** import 任何 `@/api` / `@/services` / `@/stores/{域}` —— 必须是纯展示 / 纯交互件，数据由 props 注入。沾业务即下沉到 `{domain}/` 或 `pages/`。

### 8.3 组件登记制（rule: `component-registry`）【评审】

- 新增**跨页复用**组件，**必须**登记：路径 / 场景 / 最小用法。
  - `[PLANNED]` 登记落点 `docs/infrastructure011/013.topic-project-structure.md` **尚未建立**；落地前以组件文件顶部 JSDoc 说明代替，登记文档就绪后迁入。
- 业务页**禁止**复制粘贴同一套 UI 逻辑（如连接测试、SQL 编辑器）。

### 8.4 组件 props（rule: `component-props`）【正则】

- **禁止** `props: any`；props 必须显式声明类型。
- **禁止**用 `React.FC`（React 19 下无必要，且隐式 `children`）；直接函数声明 + 参数类型。

```tsx
// ❌
const Foo: React.FC<any> = (props) => ...

// ✅
interface FooProps {
  /** 组织树数据 */
  data: OrgVo011[]
  onSelect?: (id: string) => void
}

export function Foo({ data, onSelect }: FooProps) { ... }
```

## 9. UI 与样式（rule: `ui-import` / `style-*`）【正则】

- **UI 库单一**：本 PC 工程只用 **Ant Design**；**禁止**引入 `antd-mobile`（§A5）。
- **样式方案为 SCSS**（`[PLANNED]` Tailwind CSS **未引入**，勿按 Tailwind 写类名）：
  - **唯一入口** `src/styles/index.scss`（由 `src/main.tsx` 引入）；分层顺序 `tokens → base → layout → common → antd → components → pages`，**勿随意调整**。
  - **设计令牌**在 `src/styles/_tokens.scss`（`:root` CSS 变量），运行时由 `src/config/theme.ts` 的 `applyThemeCssVars()` 覆盖；自研 DOM 取色**只读** `var(--*)`。
  - **antd 组件的尺寸 / 字号 / 行高 / 状态色**一律在 `src/config/theme.ts` 的 `buildTheme()` 用 token 定义；**禁止**在 SCSS 里写 `.ant-table` / `.ant-btn` 覆盖，也**禁止** `!important`。
- **禁止**内联 `style={{}}` 做本可用 SCSS 类表达的事（动态计算值除外）。
- **禁止**随意新增全局样式：新样式按归属放进 `src/styles/components/` 或 `src/styles/pages/`，并在入口注释的分层内定位。

## 10. 日志与错误（rule: `log-concat` / `error-*`）【正则 + 评审】

- **禁止**提交 `console.log` / `console.debug`（允许 `console.warn` / `console.error` 用于不可恢复异常，且必须带上下文）。
- **禁止**字符串拼接日志（同后端口径）；需要上下文用结构化参数或模板。
- **禁止**吞异常：`catch {}` 空块禁止；至少 `console.error` 或提示用户。
- 用户可见错误信息不得包含堆栈 / 内部细节（安全红线，同后端）。

## 11. 日期时间（rule: `datetime-format`）【正则】

- 契约格式统一 **`yyyy-MM-dd HH:mm:ss`**（见 `013.api-contract.md`）。
- **禁止**前端把 ISO 的 `T` 替换为空格来「修复」展示（§C4）。
- **展示层格式化**：`[PLANNED]` 统一工具 `src/utils/formatDate.ts` **尚未实现**；现状为各页就地用 `new Date(...).toLocaleString('zh-CN')`（如 `pages/storageCenter/julyStorage/index.tsx` 的局部 `formatDateTime`）。新增展示应**先建统一工具再复用**，不再扩散就地实现。

## 12. 禁魔法值（rule: `magic-value`）【正则】

- 状态 / 标记等取值比较**一律通过枚举或常量**，不得散落字符串字面量：

```ts
// ❌
if (row.status === '1') { ... }

// ✅
if (row.status === Status011.Enabled) { ... }
```

- 分页默认值 / 上限等用 `src/types/common.ts` 中的常量（如 `MAX_PAGE_SIZE`）。

## 14. 门禁执行顺序

```bash
./script011.sh gate
```

## 15. 命名规范速查（rule: `naming` 汇总）

> 本节是 §3.6 / §4 的**速查表**，规则与门禁映射以那两节为准。

| 后缀 / 形态 | 含义 | 所在层 |
|------|------|--------|
| `*Vo011` | 传输载荷（入参 / 出参）与实体 View Object | `types/{域}/vo.ts`、`types/{域}/view.ts` |
| `*Query011` / `*Result011` | 分页对（自带方向语义，**例外不叠 Vo**） | `types/common.ts`、`types/{域}/` |
| `Response011<T>` | 统一响应信封 | `src/types/api.ts` |
| `use*` | 自定义 Hook（camelCase，`use` 开头） | `hooks/` |
| `{域}Service.ts` | 业务编排模块（一域一个，导出**独立函数**，非 `*Api` 聚合对象） | `services/{域}/` |
| `use*Store` | Zustand store hook | `stores/` |
| `PascalCase.tsx` | 页面 / 通用组件文件 | `pages/`、`components/` |
| `camelCase.ts` | 工具 / 服务 / store / 类型模块 | 其余 |
| `SCREAMING_SNAKE_CASE` | 常量 | `types/common.ts`、`config/constants.ts` |
| 语义名 + `011` | 枚举 / 配置常量 / 自定义组件 | 全部 |
| **业务对象 + `july` 前缀** | 域实体及其文件 / 类型 / 目录（**函数名不叠 `July`**） | `types/`、`services/`、`pages/` |

**`july` 前缀四形态**（一体，细则见 §4）：

| 形态 | 写法 | 示例 |
|------|------|------|
| 文件 / 目录 | `july` + PascalCase **首字母小写**（camelCase） | `julyUser.ts` · `julyUser/` · `julyDept.ts` |
| 类型 | `July` + PascalCase + 代际后缀 | `JulyUserVo011` · `JulyRoleQuery011` · `JulyDeptTreeNodeVo011` |
| 函数 / 变量 | 动词 + `July` + PascalCase | `selectJulyUserListByPage` · `buildJulyDeptTree` |
| 组件文件 | PascalCase（含 `July`） | `EditJulyUser.tsx` · `JulyRoleList.tsx` |

**对齐依据**：后端实体 `JulyUser` / 表 `july_user` / VO 目录 `julyuser/` / URL 段 `julyUser` —— 前端四形态与之一一对应，**任何一处漏前缀都视为命名违规**（rule: `july-prefix`）。

**禁止缩写**（rule: `no-abbreviation`）：

| 禁用 | 应用 |
|------|------|
| `comm/` | `common/` |
| `conf/` · `cfg` | `config/` · `configuration` |
| `comp/` | `component/` |
| `btn` · `msg` · `img` | `button` · `message` · `image` |

- **例外白名单**：`api` / `utils` / `props` / `ref` / `src` / `env` / `config`
- `req` / `res` 作**函数参数名**可保留，作**文件名**禁用
- 门禁判定：目录名长度 ≤ 4 且不在例外表 → **人工复核**

**不加 `july` 前缀的三种情况**：① 通用领域概念字段（`auth` store 的 `user` / `token`）；② 框架级 / 跨域通用组件（`components/layout/`，以及 `[PLANNED]` 的 `components/common/`）；③ 非 IAM 的其他域（沿用各自后端实体前缀，如 `storageCenter`）。

**命名禁止项**：

- 跨目录相对路径 `../`（一律 `@/`；同目录 `./` 允许）
- `React.FC`（React 19 下无必要，且隐式 `children`）
- props 用 `any`
- 业务对象漏 `july` 前缀（裸 `user.ts` / `UserVo011` / `getUserList`）
- 把后端动词改写成前端习惯语序（`selectListByPage` ✗→ `getUserList`）
- **缩写命名**（`comm/` / `conf/` / `comp/` / `btn` / `msg`）
