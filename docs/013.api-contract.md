# 013 — 接口契约（API Contract）

> **定位**：前后端对话的**唯一契约说明** —— 契约来源 / 路径规律 / 统一信封 / 分页 / 鉴权 / 状态码 / 字段格式。
> **性质**：**项目相关**（本文档描述**本项目**的接口契约；结构与 `docs/` 内其他文件一致，内容随项目而变）。
> **配套**：后端 `klsjnh-java17-framework011`（DDD 分层）；编码规则见 [`016.coding-standards.md`](016.coding-standards.md)。
> **写法约定**：本文**只写契约的「类」**（信封 / 分页 / 鉴权 / 格式 … 这些**跨接口不变的形状**），
> **不逐条抄写每个业务接口** —— 逐条清单以**运行时 OpenAPI** 为唯一依据（见 §011）。

- 后端地址 / 前缀从**环境变量**读取，**不硬编码**

| 项 | 值 |
|----|----|

| OpenAPI JSON | `http://192.168.3.160:11610/v3/api-docs` |
| 服务名 | `klsjnh java17-framework011 API` |
| 版本 | `1.0.0` |

> 上述地址仅为**开发环境当前值**，会随环境变化；以 `015.project-info.md` 的环境变量清单为准。
>
> **⚠️ OpenAPI 的双面性**（**读源码后修正**，详见 [`019.backend-api-review.md`](019.backend-api-review.md)）：
>
> **后端实现是可靠的**（状态码与 HTTP 同步、异常处理完整、鉴权完备、双启动卫兵）。**不可靠的只是 Swagger 的「文档声明」**，具体三处：
> 1. **响应 content-type 声明为 `*/*`**（未配 `produces`）—— 代码生成器无法判断响应是 JSON
> 2. **错误响应未声明**（文档只列 `200`，但**运行时确实会返回 400/401/403/404/500**）

>
> **因此**：
> - **字段名 / 类型 / 路径 / 入参** → 以 OpenAPI 为准
> - **信封 / 状态码 / 鉴权 / 错误分支** → **以本文档 §015~§018 为准**（本文已依源码校正）
> - **Swagger 的 `responses` 段不可作为错误码依据**，但**不可据此认为后端「没有错误处理」**

## 013.路径与动作规律

**路径形态统一**：`/klsjnh/{module}/{resource}/v1/{action}`，请求与响应均为 `application/json`。

**HTTP 方法不再全 POST**（2026-09-14 后端已改造）：

| 类别 | 方法 | 传参 | 动作 |
|------|------|------|------|
| 简单读 | **GET** | query string | `getById` / `selectTree` / `selectUserMenuTree` |
| 分页读 | POST | JSON body | `selectListByPage` |
| 全部写 | POST | JSON body | `insert` / `update` / `logicDelete` / `logicDeleteBatch` / 各类特有动作 |

> **改造背景**：后端原标准 §6（rule: `api-url`）只禁路径参数、未约束 HTTP 方法，
> 门禁脚本（`tools/klsjnh-standards-lib.mjs`）又只检查前者，导致「禁路径参数 → id 只能进 body → GET 无 body → 全 POST」的连锁后果，
> **违反 HTTP 语义契约（RFC 9110）**：`getById` 等只读接口本应 safe + idempotent，标成 POST 等于对外声称 unsafe + 非幂等。
>
> **已落地修复**（详见 [`019.backend-api-review.md`](019.backend-api-review.md) §013-6）：
> 1. 门禁新增 `api-method` 规则（读动作必须 GET，写动作必须 POST）
> 2. 标准 §6 拆为 §6.1（禁路径参数）+ §6.2（方法与动作语义匹配）
> 3. Tier 3 全部 10 个读接口已改 GET，id 走 query string

```text
/klsjnh/{module}/{resource}/v1/{action}
```

| 段 | 含义 | 示例 |
|----|------|------|
| `{module}` | 模块域 | `system011`（系统域）/ `demo11`（示例域） |
| `{resource}` | 资源名（小驼峰，单数） | `julyUser` / `julyRole` / `julyMenu` |
| `v1` | 契约版本段（**固定**） | `v1` |
| `{action}` | 动作名（动词开头小驼峰） | `insert` / `selectListByPage` |

**通用动作集**（资源的标准五件套 + 资源特有动作）：

| 动作 | 语义 | 方法 | 入参 | 出参 `data` |
|------|------|------|------|-------------|
| `getById` | 按主键取单条 | **GET** | query `?id=xxx` | `{Resource}Vo011` |
| `insert` | 新增 | POST | `{Resource}InsertVo011` | `{Resource}Vo011` |
| `update` | 修改 | POST | `{Resource}UpdateVo011` | `{Resource}Vo011` |
| `logicDelete` | 逻辑删除（单个） | POST | `IdVo011` | `IdVo011` |
| `logicDeleteBatch` | 逻辑删除（批量） | POST | `IdsVo011` | `BatchDeleteResultVo011` |
| `selectListByPage` | 分页查询 | POST | `{Resource}QueryVo011` | `PageResult011<{Resource}Vo011>` |

**资源特有动作**（按资源各自定义，只举例，不穷举）：

| 资源 | 特有动作 | 语义 |
|------|----------|------|
| `julyUser` | `login` / `loginByUserName` / `logout` / `changePassword` / `resetPassword` / `assignRoles` | 会话与凭据 |
| `julyRole` | `assignMenus` | 角色授权菜单 |

| `export/v1` | （独立导出入口） | 数据导出 |

> **当前资源清单**（仅列名，不展开字段）：`julyUser` · `julyUserAudit` · `julyRole` · `julyMenu` · `julyOrganization` · `julyScheduler` · `julyConfig` · `demo11`。

## 015.统一响应信封

**所有接口**的返回体都是同一个信封 —— 前端**只需在一处解析**。

```json
{
  "statusCode": 200,
  "message": "insert success",
  "errorMessage": "",
  "timestamp": 1757823000000,
  "traceId": null,
  "data": {}
}
```

| 字段 | 类型 | 必出 | 语义 | 前端处置 |
|------|------|------|------|----------|
| `statusCode` | int | 是 | **业务状态码，与 HTTP 传输状态码保持同步**（**200 = 成功**） | `200` 取 `data`；其余走统一错误分支 |
| `message` | string | 是 | 人读消息：成功为 `"<action> success"`，失败为安全提示 | 失败时展示 |
| `errorMessage` | string | 是 | 失败详情，**仅 debug 态填充**，其他环境恒为 `""` | **不展示**（生产恒空，展示无意义） |
| `timestamp` | int64 | 是 | 信封创建时的服务器时间（epoch 毫秒） | 一般不用 |
| `traceId` | string | 否 | 链路 ID（预留）；**当前恒为 `null`** | 暂无用途 |
| `data` | 泛型 `T` | 否 | 业务载荷；无返回数据的写操作为 `null` | 成功时取 `data` |

- 类型名规律：`Response011<T>`（即 `Response011Void` / `Response011JulyUserVo011` / …）
- **解析收口一处**：信封解析只在请求客户端（`src/utils/request.ts`），业务层不再判 `statusCode`
- **`statusCode` 即 HTTP 状态码** —— 前端拦截器**同时**看 HTTP status 与 body 的 `statusCode`，二者恒一致
- **注意**：二进制下载端点（如数据导出）**不走信封**，直接返回文件流 —— 属契约内设计

## 016.分页规范

**请求**（`{Resource}QueryVo011` 的公共前缀）：

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `pageIndex` | int32 | 1 | 页码，**从 1 开始** |
| `pageSize` | int32 | 10 | 每页条数 |
| （其余） | — | — | 各资源的业务筛选条件，附在分页字段之后 |

> **服务端兜底**（`PageQuery011` 紧凑构造器）：`pageIndex` 为 `null` 或 `< 1` → 强制 `1`；`pageSize` 为 `null` 或 `<= 0` → 强制 `10`。
> **不传也能工作** —— 前端无需为分页参数做前置校验。

**响应**（`PageResult011<{Resource}Vo011>`，放在信封的 `data` 内）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `pageIndex` | int32 | 当前页码（回显） |
| `pageSize` | int32 | 每页条数（回显） |
| `total` | int64 | 总记录数 |
| `totalPages` | int64 | 总页数 |
| `rows` | `{Resource}Vo011[]` | 当前页数据 |

- **页码从 1 开始** —— 前端分页组件默认 0 基时需 `+1 / -1` 转换
- 分页响应**恒为 `rows`**，**不是** `list` / `records` / `items`

## 017.鉴权

- **方式**：签名 **JWT**，请求头 `Authorization: Bearer <token>`
- **获取**：`julyUser/login`（账号密码）或 `loginByUserName`（**免密，仅 debug / development 运行态**）→ `data.token`
- **会话载荷**（`JulyUserSessionVo011`）：`token` / `userAccount` / `userName` / `roles[]`
- **白名单**（不需 token）：2 个登录端点 + 文档路径（`/doc.html` `/v3/api-docs` `/swagger-ui` …）+ `/error`
- **令牌存放**：仅存于前端（localStorage / 内存）
- **失效处置**：收到 **401** → **清除本地会话 → 跳登录**；**不做静默重试**
- **登出**：`julyUser/logout`（记录 LOGOUT 审计），成功后清除本地会话
- **运行态**（后端 `krt.status`）：`debug` 不拒绝任何请求 / `development` 校验 token 且允许免密 / `production` 校验 token
  - ⚠️ **当前开发环境 `krt.status = debug`** —— 所以**不带 token 也能调通**。**前端不要依赖这一点**：生产必为 `production`

> OpenAPI **未声明 `securitySchemes`**（仅文档声明缺失），但**鉴权实现完整**（`GlobalAuthFilter`）。
> 契约以**实际 HTTP 行为**为准 —— 详见 [`019.backend-api-review.md`](019.backend-api-review.md)。

## 018.状态码

`statusCode` **就是 HTTP 状态码**（后端 `HttpCodeEnum011` 硬保证二者同步，`ResponseEntity.status(code)` 返回）。

| `statusCode` / HTTP | 常量 | 语义 | 前端处置 |
|---------------------|------|------|----------|
| `200` | `SUCCESS` | 成功 | 取 `data` 继续 |
| `400` | `BAD_REQUEST` | 参数或校验失败；请求体不可读 | 提示 `message` |
| `401` | `UNAUTHORIZED` | 缺失/无效/过期 token；**登录失败、账号禁用** | **清会话 → 跳登录** |
| `403` | `FORBIDDEN` | 已认证但无权限 | 提示无权限，**不清会话** |
| `404` | `NOT_FOUND` | 资源或端点不存在 | 提示 |
| `500` | `ERROR` | 服务器内部错误 | 提示 + 记录 `traceId` |

> **关键口径**：
> - **成功码是 `200`，不是 `0`**
> - **登录失败返回 `401`**（账号密码错误 / 账号禁用 / production 下免密被拒）—— 前端登录页须把 401 当「凭据错误」处理，**而非「会话失效」**
> - `401` 由 `GlobalAuthFilter` 直接写出（不经异常处理器）；`400/403/404/500` 由 `GlobalExceptionHandler` 返回

> **✅ 已修复（2026-09-14）**：`logicDelete` 入参曾分裂两态（3 个资源收 `List<string>`、4 个收 `IdVo011`）。
> 现已统一为**按单个 / 批量拆成一对动作**：
>
> | 动作 | 入参（body） | 返回 | 可用资源 |
> |------|------|------|---------|
> | `/logicDelete` | `{ "id": "xxx" }` | `{ "id": "xxx" }` | **全部 7 个资源** |
> | `/logicDeleteBatch` | `{ "ids": ["a", "b"] }` | `BatchDeleteResultVo011` | `julyUser` / `julyMenu` / `julyScheduler` |
>
> **前端封装**：`logicDelete(resource, id)` 统一可用；`logicDeleteBatch(resource, ids)` 仅上述 3 个资源提供。
> 其余资源（`julyConfig` / `julyOrganization` / `julyRole` / `demo11`）**没有批量端点**，需前端循环调用单个。
>
> **⚠️ 批量入参是对象不是数组**：`{"ids": [...]}` **而非** `["a","b"]`。请求载荷一律用具名 VO 封装，
> 不传裸集合 —— 便于后续加字段（如 `dryRun`）而不破坏契约。

## 019.字段与格式约定

| 项 | 约定 |
|----|------|
| **字段命名** | 以 OpenAPI 为准**逐字对齐**，前后端同名字段同名（`userAccount` 不写成 `username`） |
| **主键 `id`** | **字符串**（UUID），前端不做数字运算 |
| **时间字段** | OpenAPI 类型为 `date-time`；**展示层**统一 `yyyy-MM-dd HH:mm:ss`（空格分隔，**非** ISO `T`）；不做 `T`→空格字符串补丁 |
| **状态字段** | 字符串枚举（如 `julyUser.status`：`0` 禁用 / `1` 启用），**不用布尔** |
| **空值** | 可空字段返回 `null`（非省略），前端需判空 |

## 020.读接口调用形态速查（2026-09-14 改造后）

Tier 3 的 10 个读接口已由 `POST + JSON body` 改为 `GET + query string`。**前端调用方式必须同步修改。**

### 已改 GET 的 10 个接口

> **口径**：`getById` ×7 + `selectTree` ×2 + `selectUserMenuTree` ×1 = **10 个**（完整改造记录见 [020.read-endpoints-get-migration](020.read-endpoints-get-migration.md)）。

| # | 路径 | 传参 |
|---|------|------|
| 1 | `/klsjnh/system011/julyUser/v1/getById` | `?id={id}` |
| 2 | `/klsjnh/system011/julyOrganization/v1/getById` | `?id={id}` |
| 3 | `/klsjnh/system011/julyOrganization/v1/selectTree` | 无参 |
| 4 | `/klsjnh/system011/julyMenu/v1/getById` | `?id={id}` |
| 5 | `/klsjnh/system011/julyMenu/v1/selectTree` | 无参 |
| 6 | `/klsjnh/system011/julyMenu/v1/selectUserMenuTree` | 无参（操作人来自鉴权头） |
| 7 | `/klsjnh/system011/julyConfig/v1/getById` | `?id={id}` |
| 8 | `/klsjnh/system011/julyScheduler/v1/getById` | `?id={id}` |

**未改动**：`selectListByPage`（全域，保持 POST + body）、所有写操作（保持 POST + body）。

### 调用形态对比

```text
改前  POST /klsjnh/system011/julyUser/v1/getById
      Content-Type: application/json
      { "id": "u-001" }

改后  GET  /klsjnh/system011/julyUser/v1/getById?id=u-001
      (无请求体)
```

### 前端适配要点

| 项 | 说明 |
|----|------|
| **响应结构不变** | `Response011<T>` 信封一字未改，`statusCode` / `data` / `message` 照旧 |
| **鉴权头不变** | `Authorization: Bearer {token}` 照旧 |
| **参数位置变** | 从 body 移到 query；`id` 是字符串（UUID），**需 `encodeURIComponent`** |
| **错误处理不变** | HTTP 状态码与 `statusCode` 严格同步，401/403/404/500 处理逻辑无需调整 |
| **附带收益** | 读接口可用 URL 直接打开调试；浏览器/网关可缓存；网关可安全重试 |

### ⚠️ 若 api 封装层是统一 POST 的

如果前端的请求封装（如 `request.post(url, data)`）写死了 POST，需要为这 10 个接口提供 GET 通道，
**不要**用「POST 到 GET 端点」的方式绕过 —— Spring 会返回 **405 Method Not Allowed**。
