## 011.响应信封（六键固定）

所有端点统一返回六键信封；JSON 键 **camelCase**，禁止改名、删除或重排：

```json
{
  "statusCode": 200,
  "message": "select success",
  "errorMessage": "",
  "timestamp": 1789225735918,
  "traceId": "b7c1e2f0a3d94e8f",
  "data": null
}
```

| key | 类型 | 必出 | 说明 |
|-----|------|------|------|
| statusCode | int | 是 | 业务状态码，与 HTTP 传输状态码保持一致 |
| message | string | 是 | 人读消息：成功为 "<action> success"，失败为安全提示；不含内部细节 |
| errorMessage | string | 是 | 失败详情，**仅 debug 态填充**，其它环境恒为 `""`；堆栈/SQL 不出站 |
| timestamp | long | 是 | 信封创建时的服务器时间（epoch 毫秒） |
| traceId | string | 否 | 链路 id，由网关/过滤器写入；不可用时为 null |
| data | object | 否 | 业务载荷；无返回数据的写操作为 null |

## 013.状态码

| code | 默认 message | 场景 |
|------|--------------|------|
| 200 | success | 成功 |
| 400 | bad request | 参数或校验失败 |
| 401 | unauthorized | 缺失、无效或过期 token |
| 403 | forbidden | 已认证但无权限 |
| 404 | not found | 资源或端点不存在 |
| 500 | internal server error | 服务器内部错误 |

**新增常量必须先扩本表格。**

## 015.URL 结构与标准动作

- URL 结构：`/api/v1/{模块}/{动作}`（前端 `apiBaseUrl` 默认 `/api/v1`）
- 业务接口统一 **POST + JSON body**；GET 仅用于无参纯查询；禁止路径参数

| 动作 | 方法 | 说明 |
|------|------|------|
| selectOne | POST | 查询单个 |
| selectListByPage | POST | 分页查询 |
| insert | POST | 创建 |
| update | POST | 更新 |
| logicDelete | POST | 逻辑删除 |

## 016.前端请求行为（pc-admin 实现）

封装位置 `src/api/request.ts`，由 `src/config/appConfig.ts` 的数据模式（mock/api）控制是否启用：

- **自动解包**：`statusCode === 200` 返回信封 `data`；非 200 抛 `ApiError`（message 取 `errorMessage || message`）
- **超时**：8 秒（AbortController）
- **失败回退**：读取类请求失败时 store 保留本地 mock 数据，页面不白屏
- **乐观更新**：写操作本地先行生效 + `fireApi` 静默请求；失败仅记录到顶栏模式下拉的"最近错误"，不打断交互

已对接动作清单：

| 模块 | 动作 |
|------|------|
| menu | selectListByPage · insert · update · logicDelete · move |
| role | selectListByPage · insert · update · logicDelete · updatePermission |
| roleUser | insert · logicDelete |
| notification | selectListByPage · read · readAll · logicDelete |

> 联调：`node mock-server.mjs [端口]` 启动测试后端（返回本契约信封格式），模式下拉把 API 地址填为 `http://localhost:{端口}/api/v1`。
