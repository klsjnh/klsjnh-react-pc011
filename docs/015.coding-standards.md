# 015 — 前端编码规则（Coding Standards）

> 编码规则的**事实来源**：本仓库现行代码风格。新增代码必须遵循本文档；与后端 [`klsjnh-java17-framework011/docs/015.coding-standards.md`](../../../java17/klsjnh-java17-framework011/docs/015.coding-standards.md) 平行，互不适用。
> 强制方式标注：【铁律】不可违反 ·【评审】人工评审项 ·【构建】`npm run build` / `tsc` 可拦【约定】团队共识。

## 0. 铁律（Mandatory）

1. **所有接口 / 类型定义必须放在 `src/types/`**，禁止散落在 `pages/`、`components/`、`services/`、`stores/`、`mock/`、`utils/`、`config/`、`api/`。
   - 需要时可在原处 `import type` + `export type { X }` 做转发，但**定义只允许有一处（types）**。
2. **按模块目录组织**：后端 `system011` 下每个模块一个目录 `src/types/system011/<module>/`：
   - `vo.ts`：后端契约类型（DTO/VO，与 swagger 一一对应）
   - `view.ts`：前端 UI 视图类型（表格行、store 状态、表单值等）
   - `index.ts`：出口，`export * from './vo'; export * from './view';`
   - 跨模块通用类型：`src/types/system011/common.ts`
3. 通用（非模块专属）类型：
   - UI 通用：`src/types/view/`（layout / auth / ui / toast / notification / transfer / appConfig / common）
   - 请求信封：`src/types/api.ts`；store 工厂：`src/types/store.ts`
4. 禁止在业务代码里 `interface X {}` / `type X = …` 定义新类型；只能从 `@/types/...` 引入。组件 Props 若需跨文件复用，同样必须放 `types`。

## 1. 文件头注释【约定】

每个页面 / 组件 / store / service 源文件以中文块注释开头，说明**职责 + 关键交互**：

```tsx
/**
 * 菜单管理页（julyMenu）- PC 端
 * 左侧：菜单树，支持右键菜单与拖拽调整层级
 * 右侧：当前菜单的编辑表单
 */
```

## 2. 命名规范【评审】

- **系统管理模块页面**：`julyXxx`（全单词、禁缩写），位于 `src/pages/system011/`；多文件模块用 `julyXxx/index.tsx` 目录，弹窗/子组件就近放同目录（如 `JulyUserFormModal.tsx`）
- **service**：`src/services/system011/julyXxxService.ts`
- **store**：`src/stores/system011/julyXxxStore.ts`，导出单例 + `useXxxState()` Hook
- **组件**：`src/components/` 下 PascalCase 文件 + 同名组件
- **路由路径**：系统管理模块为 `/system011/julyXxx`（如 `/system011/julyUser`）
- **编号文档**：`docs/{编号}.{名称}.md`，编号规则见 [`011.agreements.md`](011.agreements.md)

## 3. PC 页面统一写法【评审】

UI 组件库统一使用 **Ant Design（antd 5/6）**；`src/styles/global.css` 仅保留布局辅助与少量自定义类，禁止内联 `style` 堆砌：

| 场景 | 组件 |
|---|---|
| 页头 | `page-header`（h2 + p） |
| 工具栏 | `page-toolbar`（toolbar-left / toolbar-right）+ antd `Input`/`Select`/`Button` |
| 数据表格 | antd `Table`（分页、排序、树形数据） |
| 弹窗 | antd `Modal`（经 `src/components/Modal.tsx` 统一入口或直接用） |
| 表单 | antd `Form` + `Form.Item` 规则校验 |
| 消息 | `toast`（`src/utils/toast.ts`，底层 antd message） |
| 状态徽标 | antd `Tag` |

页面骨架：

```tsx
<div>
  <div className="page-header"><h2>标题</h2><p>副标题</p></div>
  <div className="page-toolbar">…搜索 / 新增按钮…</div>
  <Card className="table-wrapper"><Table … /></Card>
</div>
```

## 4. 状态管理模式【评审】

统一使用 **zustand**（`@/stores/createStore` 或 zustand 原生 `create`），禁止再自研发布订阅：

```ts
import { createStore } from '@/stores/createStore';
```

- 需要 localStorage 持久化的 UI 状态统一走 `src/stores/uiStore.ts`（侧边栏收起、树的展开/选中）
- 跨页面共享数据必须进 store（如通知未读数），禁止只放页面本地 state

## 5. 分层与 API 层【评审】

**依赖方向单向**：`page → service → store`；`page → store` 只读。

- `service`（`src/services/system011/*Service.ts`）：所有业务操作（含 CRUD 编排），可写 store 状态
- `store`（`src/stores/system011/*Store.ts`）：只负责状态 + 本地持久化，**不调用 service**
- `page`：事件调 service、渲染读 store，不写业务

接口调用一律通过 `src/api/request.ts`：
- `api.post(action, body)`（自动解包信封 `data`）与 `fireApi(action, body)`（写操作乐观更新）
- 动作命名对齐 [`016.api-contract.md`](016.api-contract.md)：`selectListByPage / insert / update / logicDelete`
- 禁止在组件里直接 `fetch`

## 6. 路由【评审】

- 使用 `react-router-dom`（`HashRouter`）；`App.tsx` 负责登录态分流，`pages/home/index.tsx` 负责登录后页面分发
- 新增页面：在 `pages/home/index.tsx` 的 `PAGE_MAP` 注册，并从 `pages/` 懒加载
- 侧边栏菜单：`config/global.ts` 的 `GLOBAL_MENUS`（开发态）/ 后端 `selectUserMenuTree`（非开发态）两处同步
