# 015 — 前端编码规则（Coding Standards）

> 编码规则的**事实来源**：本仓库现行代码风格。新增代码必须遵循本文档；与后端 [`klsjnh-java17-framework011/docs/015.coding-standards.md`](../../../java17/klsjnh-java17-framework011/docs/015.coding-standards.md) 平行，互不适用。
> 强制方式标注：【评审】人工评审项 ·【构建】`npm run build` / `tsc` 可拦【约定】团队共识。

## 1. 文件头注释【约定】

每个页面 / 组件 / store 源文件以中文块注释开头，说明**页面职责 + 关键交互**：

```tsx
/**
 * 菜单管理页（julyMenu）- PC 端
 * 左侧：菜单树，支持右键菜单（新建子菜单/编辑/删除）与拖拽调整层级
 * 右侧：当前菜单的编辑表单（右上角保存），点击树节点切换
 */
```

## 2. 命名规范【评审】

- **系统管理模块页面**：文件与组件同名 `julyXxx`（全单词、禁缩写），位于 `src/pages/system011/`；单页直接放文件，多页模块用 `julyXxx/index.tsx` 目录
- **store**：`src/stores/xxxStore.ts`，导出 `xxxStore` 单例 + `useXxxState()` Hook
- **组件**：`src/components/` 下 PascalCase 文件 + 同名组件（`OrgPickerModal.tsx`）
- **路由路径**：全单词小写（`/menu` `/user` `/permission` `/organization`），禁止复数与缩写
- **编号文档**：`docs/{编号}.{名称}.md`，编号规则见 [`011.agreements.md`](011.agreements.md)

## 3. PC 页面统一写法【评审】

页面统一使用 `src/styles/global.css` 全局类拼装，禁止引入第三方 UI 库、禁止移动端残留模式（`PageHeader` 返回箭头 / 全宽按钮 / `className="page"` 容器）：

| 类 / 结构 | 用途 |
|---|---|
| `page-header`（h2 + p） | 页头 |
| `page-toolbar`（toolbar-left / toolbar-right） | 工具栏（搜索 / 主操作按钮） |
| `table-wrapper` | 卡片容器（可作面板加 padding） |
| `data-table` + `btn-link`（`danger` 红字） | 数据表格与行内操作 |
| `btn btn-primary / btn-default / btn-danger / btn-sm` | 按钮 |
| `status-badge status-active / status-inactive` | 状态徽标 |
| `modal-overlay / modal-container / modal-header / modal-body / modal-footer` | 弹窗 |

页面骨架：

```tsx
<div>
  <div className="page-header"><h2>标题</h2><p>副标题</p></div>
  <div className="page-toolbar">…搜索 / 新增按钮…</div>
  <div className="table-wrapper"><table className="data-table">…</table></div>
</div>
```

## 4. 状态管理模式【评审】

统一使用 `useSyncExternalStore` 自研 store（禁止引入 redux/zustand 等三方库）：

```ts
let state: XState = { ... };
const listeners = new Set<() => void>();
function getSnapshot(): XState { return state; }
function subscribe(l: () => void) { listeners.add(l); return () => { listeners.delete(l); }; }
function emit() { state = { ...state }; listeners.forEach(l => l()); }

export const xStore = { getSnapshot, subscribe, load: async () => { ... }, /* 动作 */ };
export function useXState(): XState {
  return useSyncExternalStore(subscribe, getSnapshot, getSnapshot);
}
```

- 需要 localStorage 持久化的 UI 状态统一走 `src/stores/uiStore.ts`（如侧边栏收起、树的展开/选中）
- 通知未读数等跨页面共享数据必须进 store，禁止页面本地 state（顶栏无法感知）

## 5. API 层【评审】

- 一律通过 `src/api/request.ts`：`api.post(action, body)`（自动解包信封 `data`）与 `fireApi(action, body)`（写操作乐观更新）
- 动作命名对齐 [`016.api-contract.md`](016.api-contract.md) 标准动作：`selectListByPage / insert / update / logicDelete`
- store 内用 `isMockMode()` 分流：mock 走内置数据，api 模式读取失败**回退本地数据**，写入失败静默记录
- 禁止在组件里直接 `fetch`

## 6. 路由【评审】

- `App.tsx` 的 `pageMap` 增加页面；新页面组件从 `pages/` 懒加载导入
- 侧边栏（`SidebarLayout.tsx` navMenus）与 `mock/menuConfig.ts` 需同步登记
