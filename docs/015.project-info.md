## 011.Project Scope & Position

React 19 中后台**前端技术底座（PC 端）**，供业务系统直接作为起点或参考样板。包含组织、用户、角色、权限（RBAC）等核心管控能力，并已接入数据服务（`datasource`，目录 dataservice011）、存储中心（`storageCenter`）、AI 中心（`aiCenter`：模型供应商管理 + AI 聊天/推理，后者对接 `julyAiInference/chat/stream` SSE 纯文本协议）、消息中心（`messageCenter`：出入站模板/通道/消息）等业务域。

- **端形态**：本工程为 **PC 端**（Ant Design）；移动端为**独立工程**，不混装 UI 库（见 [017.tech-debt-redlines](017.tech-debt-redlines.md) §A5）
- **配套后端**：`klsjnh-java17-framework011`（DDD 分层）；契约以运行时 OpenAPI 为准，见 [013.api-contract](013.api-contract.md)
- **数据模式**：内置 **Mock / API 双模式**，运行时可在顶栏切换，默认 mock（详见 §018）
- **分层主线**：`Page / Component → Service（业务编排）→ API（`src/api/request.ts`）`，Store 持有状态并由 Service 写入
- **⚠️ 后端换版（2026-09-20，11610 → 11160）后本项目的两处非现役内容**：低代码（`lowcode011` / `julyMetadata`）与业务建模（`julyBusinessModeling`）已随低代码迁往新项目，前端侧边栏入口已隐藏（见 `src/stores/system011/julyMenuStore.ts` 的 `HIDDEN_NAV_ROUTES`），页面 / service / mock / types 代码**整体保留待处置**；`aicenter` 的 `julyAiPrompt`（提示词，5 端点）与 `datasource` 的 `julySql` / `julySync` **未接入**（契约已落快照，页面未开发）
- **⚠️ 后端换版（2026-09-24，11160 → 11130，新契约 194 端点）**：`julyMenu` / `julyOrganization` 从 `system011` 迁至 **`iam`**（调用传 `IAM_BASE`，签名不变）；`julyAiPrompt` 5 端点删除、由 **`julyAiDomain` 17 端点**取代（前端已于 2026-09-21 完成重构）；新增 `julyPermCatalog`（对象权限）与 storage/ai 的 `getWithChildren` / `saveWhole` 等能力。方案见 [requirement013/013.backend-realign-11130](requirement013/013.backend-realign-11130.md)，快照 `contracts/2026-09-24-openapi.json`。

## 016.Layering & Dependency Rules

```text
Page / Component
      │  读状态
      ▼
   Store（zustand：全局状态容器）
      ▲  写状态
      │
   Service（业务编排：拼参 / 调 api / 写 store / 刷新列表）
      │
      ▼
   API（src/api/request.ts：mock 分流 + 信封解包 + 401 收口）
      │
      ▼
   Backend（或内置 mock）
```

| 层 | 职责 | 可依赖 | 禁止 |
|----|------|--------|------|
| `types/` | 横切契约：DTO / VO / Store 接口 / 枚举常量 | 无 | 依赖任何运行时模块（纯类型） |
| `utils/` | 无 UI 基础设施、纯函数 | types | import 业务域 |
| `api/` | **物理请求收口**：`request.ts` 一处分发 mock/真实后端并解包信封 | utils / types / stores(auth token) | 写业务逻辑、做数据转换 |
| `services/` | **业务编排**：拼装参数、调用 api、写 store、驱动列表刷新 | api / stores / types | 碰 React / 碰 UI（`.ts`，无 JSX） |
| `stores/` | **状态容器**：全局状态与本地持久化（zustand） | types | 含 JSX |
| `hooks/` | 逻辑复用（如 `useTableFillHeight`） | stores / services / types | 含 JSX（纯逻辑用 `.ts`） |
| `components/` | 全局通用 UI 与布局框架 | hooks / stores / types | 写业务页面逻辑 |
| `pages/` | 页面视图：拉数（经 service）与交互组装 | 全部 | 直连 `src/api/request.ts` 绕过 service |
| `config/` | 应用级静态配置：路由表 / 主题 / 数据模式 | types | 写业务逻辑 |

**实际边界口径（以代码为准）**：

- `pages/` **不直连** `api/request.ts`（已核实零命中），一律经 `services/`。
- **`services/` 会写 `stores/`**（本项目采用「service 编排 + 写 store」）；唯一反向例外是 `stores/authStore.ts` 直接调用 `services/system011` 的登录/登出。
- **待裁决**：`016.coding-standards` §7 与 `017.tech-debt-redlines` §A3/§A4 表述与上述现状存在张力（service 是否可写 store、工厂化 CRUD 是否强制），尚未裁决 —— 见 [2026-09-17 工作日志](2026-09-17.md) §三。

**两条硬约束**：

1. **信封解析只在一处** —— `src/api/request.ts`，各层不再判 `statusCode`（见 017 §C5）
2. **状态只有一套** —— Zustand 工厂，禁手写 pub/sub（见 017 §A1）

## 017.Core Design Decisions

1. **契约不在文档中写死**：后端地址与 API 前缀**不固化在文档 / 常量里**，以运行时 OpenAPI 为唯一契约，快照落盘至 `docs/contracts/`（见 017 §C1/C2）。
2. **类型按域分层**：各业务域 VO 放 `types/{域}/`，请求出入参契约与视图类型分离，**禁单文件堆积**（见 017 §B1）。
3. **字段名唯一真源是 OpenAPI**：前端类型字段名与契约**逐字一致**，不做「前端更顺眼」的改名（见 017 §B2/C3）。
4. **日期格式后端负责**：前端只做展示层格式化，不做 `T` 替换补丁（见 017 §C4）。
5. **请求处置口径**：401 统一在 `request.ts` 收口 → **清本地会话 → 由路由守卫（`App.tsx` 订阅 `authStore`）跳登录**；凭据类接口（login / logout）的 401 按「凭据错误」处理，不触发全局登出；**不做静默刷新 / 重试**（权威口径见 [013.api-contract](013.api-contract.md) §015）。
6. **门禁随提交入口强制**：`tsc --noEmit` → ESLint → 规范自检脚本，见 §018；**不使用 git hooks**（与后端口径一致，见 [016.coding-standards](016.coding-standards.md) §14）。

## 018.构建与运行

```bash
pnpm install              # 安装依赖（锁文件 pnpm-lock.yaml）

pnpm dev                  # 开发服务器（Vite，端口 11131）
pnpm build                # 生产构建（vite build，产物 dist/）
pnpm preview              # 预览构建产物
pnpm typecheck            # tsc --noEmit
pnpm lint                 # ESLint
pnpm standards            # 规范自检脚本

./script011.sh gate       # 门禁：tsc → eslint → 规范自检
./script011.sh build011   # 门禁 + 生产构建
./script011.sh start011   # 启动开发服务器
./script011.sh            # 默认：门禁 → 版本号自增 → 提交白名单路径 → push
```

- **门禁顺序**（`016.coding-standards` §14）：`tsc --noEmit` → `eslint .` → `node tools/check-klsjnh-react-standards.mjs`；**全通过才允许提交**。默认提交路径同样先过门禁，且只 `git add` 白名单路径（`script011.sh` 内 `TRACKED_PATHS`），不使用 `git add .`。
- **端口与代理**：dev server 端口 `11131`（`vite.config.ts`）；`/klsjnh` 代理到后端 `http://192.168.3.160:11130`（2026-09-24 换版）。⚠️ 该地址目前**硬编码在 `vite.config.ts`**，与 §C2「地址不固化」相悖，待改为环境变量。
- **环境变量**（样例见 `.env.example`；本机私有覆盖入 `.env.local`，不入库）：
  - `VITE_DATA_MODE`：`mock`（默认）| `api`
  - `VITE_API_BASE_URL`：API 模式基地址，默认 `/klsjnh/system011`
  - `VITE_RUN_STATE`：`development` | `production`（development 下支持免密登录）
  - 另可在顶栏切换并持久化到 localStorage（`pc011-data-mode` / `pc011-api-base-url`）
- **前置**：Node 18+（本机 v22.23.2）· pnpm 10（可用 `corepack enable pnpm`）· git 仓库已 init 且配置 remote
