**`previewDdl` 的生成规则**（源码 `MySqlMetadataDdlGenerator`，实证见 §020.6）：

- 表名统一 **`lc_` 前缀** → `CREATE TABLE IF NOT EXISTS \`lc_<objectName>\``
- 首个 `id` 类型字段作主键；**一个都没有时自动补** `` `id` VARCHAR(33) NOT NULL COMMENT 'primary key' ``

- 标识符白名单 `^[A-Za-z_][A-Za-z0-9_]{0,59}$`；非法标识符 / 未知类型 / 无字段 → **400**
- 表尾 `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='<描述>'`（无分号）

## 020.3 B 档 · 契约错配（⚠️ 本轮修正的 5 处）

这 5 处接口**一直都在**，是前端调错了。方法错配在本项目后端表现为 **HTTP 500**（`HttpRequestMethodNotSupportedException`），**不是 405** —— 所以「看着像后端炸了」，实际是前端打错方法。

| # | 位置 | 修正前（错） | 修正后（对） | 症状 |
|---|------|-------------|-------------|------|
| 1 | `getModelingById` | `api.post(getById, {modelCode})` | `api.get(getById, {id})` | 打开已有模型必 500 |
| 2 | `getModelData` | `api.post(getModelData, {modelCode})` | `api.get(getModelData, {id})` | 「获取模型数据」必 500 |
| 3 | `probe` 消费形状 | 期望 `columns: [{name,type}]` | 消费 `fieldData: FieldVo011[]` | 探针结果页空白 |
| 4 | 输出嵌套层级 | `fieldData` 当顶层读 | `fieldData` 嵌在 `metaData` 下 | 「字段数」恒为 0 |
| 5 | 字段子项字段名 | `fieldCode/fieldName/columnName/dataType/...` | `code/name/fieldType/length/notNull/defaultValue` | 子表全空 / 提交被忽略 |

> **`FieldType011` 是两侧共用的类型枚举**（12 值：`id / status / create_by / update_by / create_time / update_time / string / int / float / date / boolean / text`）—— 这正是「建模 → 元数据」能无损搬运的前提。
> 前端把旧写法 `varchar/bigint/datetime/...` 全部换成了 `FieldType011` 口径（`FIELD_TYPE_011_OPTIONS`）。

### 020.4.3 占位的三条硬约束（写在这里防后人踩）

1. **状态是内存态**（`Map`），**刷新即重置** —— 这是占位实现的固有局限，不是 bug。
2. **绝不静默**：运行时页顶部常驻橙色 `Alert`「数据 CRUD 为前端占位实现（PENDING-BACKEND）」；设计器的发布类动作按钮带 `🧪` 标记 + 新建对象（无 `objectName`）时**禁用**。
3. **与真后端同构**：占位接口的入参 / 出参形状**照抄老项目 `metadata.ts` 的类型**（`ImportDataResult` / `OpenApiConfigResult` / `RuntimeMenuRow` …），后端补齐后**调用方零改动**。
4. **版本号语义对齐后端**：`pendingPublish` 生成 `0.0.1` 递增**字符串**（非整数递增）—— 对齐后端 039 §021 风险条「version 语义对齐老 `version011`」；物化表名前缀统一 `lc_`（与 `TABLE_PREFIX` 一致）。

## 020.9 未决 / 风险

| # | 项 | 说明 |
|---|----|------|
| 1 | **`publishStatus` / `version` 是假数据** | `listModels` 与 `load` 返回的 `publishStatus` 恒为 `'draft'`、`version` 恒为 `''` —— 后端**硬编码**（`JulyMetadataDesignerUseCase` 源码），发布态列虽已 DDL 建好但 UseCase 未读取。**前端不得据此判断发布状态**（设计器页仍用占位 `refreshDesignerState` 的本地态）。 |
| 2 | **`load` 缺参回 500 而非 400** | `GET /load` 不带 `objectName` → **HTTP 500**（`MissingServletRequestParameterException` 未被 `GlobalExceptionHandler` 映射为 400）。前端须自行保证传参。同类 GET（`previewDdl` / `getById` / `getByObjectName`）同理。 |
| 3 | **两组口径并存** | 038「一主三子」（长键名）+ 039「MetaDTO」（短键名、三子顶层）同时有效。**同一处代码不得混用**；设计器页目前仍走 038 口径（已验收），MetaDTO 接口仅供新场景（如建模直通）。 |
| 4 | **枚举未展开** | `DisplayType011` / `ServiceObjectType011` / `ServiceParamType011` 后端 Swagger 未展开。运行时的「服务开关」判定同时认 `serviceCode`（insert/update/…）与 `objectType`（query/save/…），**无匹配行 = 视为开启**（与老项目 `enabled !== false` 一致） |
| 5 | **`displays` 无 `scene`** | 老项目 displays 带 `scene: list\|form\|query` 三态，新 VO **只有 `componentType` / `displayType`** —— 故运行时页派生规则改为「列表=displays、表单=fields 剔审计列、查询=前 4 个文本/状态列」，非等价移植 |
| 6 | **公共列不自动补** | 元数据保存时后端**不会**自动加 `id/status/create_by/...`（与建模侧 `replaceFields` 同款语义）→ 前端提交必须带全字段集。**例外**：`previewDdl` 会在无 `id` 字段时自动补主键列。 |
